Fracture: Fine-Tuning an LLM on Cybersecurity Data

June 2026 • Research Project

The Goal

I wanted to understand how large language models actually learn — not from a textbook, but by doing it myself. Fracture is a 3-phase self-directed ML research project: first fine-tune an existing model on cybersecurity data, then build a transformer from scratch in pure PyTorch, then build real-world cybersecurity ML tools.

The question driving Phase 1: can a small, consumer-grade LLM (1.1B parameters) be meaningfully improved on cybersecurity reasoning through targeted fine-tuning on a modest dataset?

Phase 1 — Fine-Tuning TinyLlama

The base model is TinyLlama-1.1B-Chat-v1.0 — small enough to train on consumer hardware, large enough to demonstrate meaningful learning. The fine-tuning method is LoRA (Low-Rank Adaptation), which adds trainable rank-16 matrices to 6 attention/MLP layers while keeping the base weights frozen. This keeps VRAM usage low and training fast.

Model: TinyLlama-1.1B-Chat-v1.0
Method: LoRA (r=16, 6 target modules, ~9.9M trainable params out of 1.1B)
Training: 1000 steps, cosine LR schedule, early stopping
Hardware: NVIDIA RTX 4070 (12GB VRAM), bf16 precision
Eval: 15 cybersecurity questions, scored by response length + keyword density

The Dataset Problem

Getting to a model that actually improves took four iterations, and the bottleneck was almost always the dataset — not the training code.

v1 & v2 Used the MMLU computer_security and security_studies subsets directly from HuggingFace. The benchmark showed a −19.6 average regression — the fine-tuned model was worse than the base. The problem: MMLU answers are 3–10 words long (multiple choice answer text). Training on brevity caused the model to give shorter, shallower answers than the baseline on open-ended questions.

v3 Added 56 CTF writeup examples and 68 synthetic QA pairs. Some improvement — average regression narrowed to −9.7 — but the MMLU short-answer problem still dominated.

v4 Root cause fixed. I replaced all 231 MMLU examples with expanded 100–200 word technical explanations generated via a larger local model (qwen3-coder), giving each question a proper answer rather than a bare letter choice. Combined with the CTF data, 68 synthetic examples, and 200 expanded CVE descriptions, the final dataset had 634 examples. Training on this achieved +5.2 average improvement over baseline.

What I Learned

The biggest lesson was that dataset quality matters far more than training hyperparameters. Three iterations failed not because of bad training code, but because the answers were too short to teach the model anything useful. Once I fixed the data, the model improved on the first try.

The 5 topics that still regress or stall (reverse shell, fuzzing, XSS/CSRF, OSINT, credential stuffing) are the targets for v5 — 50 additional examples with detailed technical answers have already been generated for these topics specifically.

LoRA is genuinely powerful for constrained hardware. 9.9M trainable parameters out of 1.1B (0.89%) was enough to meaningfully shift the model's knowledge in a specific domain, in under an hour on a consumer GPU.

What's Next

Phase 1 v5 — targeted fine-tuning on the 5 regressing topics
Phase 2 — build a small transformer (~0.5M params) from scratch in pure PyTorch, character tokenizer, train on the same dataset for direct comparison
Phase 3 — real cybersecurity ML tools: malware classifier (PE feature extraction), intrusion detection (CICIDS-2017 network flows), log anomaly detection (Isolation Forest + Autoencoder), vulnerability predictor (C/C++ static analysis)
